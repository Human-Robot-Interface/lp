# 人とロボットの境界線

展示のランディングページと、配布する紙面をつくるツール一式。

コンセプトは [concept/concept.md](concept/concept.md)。

## 構成

```
index.html              トップページ（静的。ビルド不要）
assets/css/style.css
assets/js/main.js       境界線スライダのみ
assets/img/
  halftone-qr.png       ハーフトーンQR（★プレースホルダ。差し替えること）
ar/index.html           MindAR による画像トラッキングAR
tools/
  halftone_qr.py        ハーフトーンQR生成
  make_sheet.py         配布用の紙面を1枚のPNGに組む
```

## サイト

ビルド不要の静的サイト。ローカル確認は次のとおり。

```sh
python -m http.server 8000
# http://localhost:8000
```

GitHub Pages / Netlify にそのまま置ける。

### 設計の約束

情報量で押す（重慶大廈・夜市の看板の重なり）。ただし土台は1本のグリッドで、
混沌は「層の重なり」でつくる。無秩序に置いているわけではない。

**色の役割を固定する。**

| 色 | 意味 |
| --- | --- |
| 白（明朝） | 人間の言葉 |
| シアン（等幅・発光） | 機械の言葉 |
| 赤 | 問い／境界そのもの |
| 琥珀・マゼンタ・ライム | 看板のネオンにのみ使用 |

- **発光するのは機械側だけ。** ネオンは装飾ではなく「どちら側か」の標識。
- **明朝＝人間の言葉、等幅＝機械の言葉。** この対応を最後まで崩さない。

**言語の層。** 日本語を主、英語・繁体字・韓国語を副に置き、さらに機械語
（UTF-16 / UTF-8 / Base64 / モールス / 点字 / 2進）を重ねる。年表では
各時代にその時代の符号を対応させている ── 音＝モールス、文字＝点字、
映像＝hex、思考＝2進。

**罫線は1pxのgapではなく各セルのborderで引く。** gap方式だと余ったグリッド
セルが色の塊になって穴が空いて見えるため。`.grid` `.era` `.refs` `.read`
すべてこの方式。

境界線スライダは、同じ一文を人間可読（明朝）と機械可読（コードポイント）の
2層で重ね、クリップ位置を動かして境界を見せている。ページの主役はこれ。

## 紙面をつくる

### 1. ハーフトーンQR

人間の目には画像に見え、機械にはQRとして読める1枚を生成する。

```sh
pip install segno pillow numpy opencv-python-headless

python tools/halftone_qr.py \
  --image path/to/face.png \
  --content "https://example.com/" \
  -o assets/img/halftone-qr.png \
  --print-mm 90
```

`--image` と `--content` は任意のものを渡せる。生成後に OpenCV で実際に
デコードできるか検証し、「1モジュール何pxで撮れば読めるか」を出力する。

主なオプション:

| オプション | 効果 |
| --- | --- |
| `--margin auto` | 既定。読める範囲で最も絵が濃くなる値を自動探索する |
| `--target-ppm` | auto が満たすべき読取水準。小さいほど厳しく、絵は薄くなる |
| `--version` | 大きいほど絵は細かく、モジュールは小さい。既定15 |
| `--subpixels` | 1モジュールの分割数。5が標準 |
| `--plus` | 読取は安定するが絵は粗くなる |
| `--damage` | 意図的に壊す演出（後述） |
| `--preview` | 離れて見たときの見え方を書き出す |

うまく出ないときは、**元画像のコントラストが高く、形が単純なもの**にする。
細部の多い画像はモジュール解像度に負けて潰れる。

> **`concept/qrimage.png` をQRの素材に使わないこと。**
> ハーフトーンQRが運べるのは低周波（大きな面の明暗）だけで、この絵の情報は
> ほぼ全部が高周波（細かい回路・9枚の写真・小さな文字）。しかも9タイルが
> 同じ濃度なので大きな明暗構造が残らない。実際に通すと v25 でようやく
> 「Select images of 'HUMANITY'」の文字とレイアウトが読める程度で、
> 9枚の写真は全部潰れる。この絵は紙面そのものに使う。

### 2. 紙面に組む

配布物は**A4を1枚だけ**。主役は `concept/qrimage.png`（CAPTCHA画面の絵）で、
下の帯にQRと最小限の文字を置く。

```sh
python tools/make_sheet.py \
  --qr assets/img/halftone-qr.png \
  -o sheet.png \
  --expect "https://example.com/"
```

この絵をそのまま使うのには理由がある。

- すでに**空欄の「I'm not a robot」チェックボックス**が描かれている
  → ARで埋める対象が絵の中にある
- 細部が多く非対称で高コントラスト → **MindARの追跡ターゲットとして理想的**

`--bg auto`（既定）が絵の四隅の色を拾って紙の地色にするので、絵が紙に溶けて
1枚の紙面として読める。`--keep-border` を付けると絵の外枠を残す。

**チェックボックスの位置は自動検出される。** 絵の中から「塗りつぶされていない
青い正方形」を探し、ARで使う座標に変換して出力する:

```
--- ARオーバーレイ座標（ar/index.html に貼る） ---
チェックボックス中心: x=-0.1660  y=-0.0309  幅=0.0388
```

この値を `ar/index.html` の `#check` の position に入れる。目分量で合わせない
こと。紙面のレイアウトを変えたら再実行して貼り直す。`--mark` を付けると
検出位置に枠を描くので、ずれていないか目視できる。

組み上げた状態でQRが読めるかも再検証する。

### 印刷時の注意

- **マット紙で刷る。** 光沢紙は照明を反射してスキャンできなくなる。
- 1モジュール 0.8mm 以上を確保する（`--print-mm` が判定してくれる）。
- 最終確認は必ず実機のカメラで。複数機種で試すこと。

## AR

`ar/index.html` は MindAR の画像トラッキングを使う。iOS Safari は WebXR の
image tracking に対応していないため、実用的な選択肢はこれか 8th Wall になる。

### 動かすための前提（ここで必ず一度つまずく）

**1. `file://` で開かない。**
オリジンが `null` になり `targets.mind` の fetch が CORS で落ちる。必ず
サーバ経由で開くこと。

**2. カメラは secure context でしか起動しない。**
`getUserMedia` は **https か localhost** でしか動かない。`file://` はもちろん、
LAN の `http://192.168.x.x` でも起動しない。実機のスマホで試すときは:

- **推奨** — GitHub Pages / Netlify に上げる（https が付く）
- トンネルを通す — `npx localtunnel --port 8000` / `cloudflared tunnel --url http://localhost:8000`
- PC の Chrome で試すだけなら `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
  に `http://192.168.x.x:8000` を登録する（開発時のみ）

**3. `targets.mind` を先に生成する。**
未生成のまま開くと `Failed to fetch` になる。下記の手順で作る。

`ar/index.html` は起動前にこの3つを検査し、どれが欠けているかを画面に出す。
コンソールの `Tracking Prevention blocked access to storage` や
`useLegacyLights` の警告は無害なので無視してよい。

### targets.mind の作り方

1. https://hiukim.github.io/mind-ar-js-doc/tools/compile を開く
2. **紙面全体のPNG**（`make_sheet.py` の出力）をアップロード
3. 出力された `targets.mind` を `ar/` に置く

> **マーカーはQR単体ではなく紙面全体にすること。**
> QRの格子は自己相似で特徴点に乏しく、追跡が安定しない。タイトル・帯・
> CAPTCHA枠まで含んだ非対称な絵をターゲットにする。

オーバーレイの座標系は「マーカー画像の幅 = 1」、原点は紙の中心。紙面の
レイアウトを変えたら `ar/index.html` の `position` を合わせ直す。

## 「壊れたQR」について

`--damage` はデータ領域を塊で潰す演出用のオプション。

よく言われる「誤り訂正レベルHは30%まで復元できる」は**誤り**で、30%は
誤り訂正符号の割合。位置が未知の誤りは1つ訂正するのにEC符号を2つ消費する
ため、実際に耐えられるのはコードワードの15%程度。

このリポジトリでの実測値:

| 条件 | 限界 |
| --- | --- |
| ほぼ素のQR（塊で潰す） | 10% 前後 |
| ハーフトーンQRと併用 | 5% 前後 |

同じ被害率でもバラバラに反転させると、汚れるコードワードが増えてもっと
早く読めなくなる（15%の散乱で復元不能）。破壊の度合いを段階的に見せる
展示にするなら、**0 → 5 → 10%** 程度の刻みで用意する。
